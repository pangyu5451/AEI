# AGG 基线复现审计

## 审计范围

- 数据集：PU
- 源工况：`N15_M01_F10`、`N15_M07_F04`、`N15_M07_F10`
- 目标工况：`N09_M07_F10`
- 类别数：14
- 训练样本：每类每工况 200 个窗口
- 测试样本：每类目标工况 50 个窗口
- 窗口长度：1024
- 归一化：`mean-std`
- epoch：60
- 种子：2026
- GPU：RTX 3080 Ti，CUDA 12.8，PyTorch 2.11.0+cu128

## 代码一致性

已逐项对照原始 `DG_main.py`、`utils/train.py`、`datasets/PU_bearing.py`、`models/extractor.py` 和 `models/classifier.py`：

- 14 类映射一致；
- 四个工况编号一致；
- 原始信号提取路径一致；
- 窗口长度和样本数量一致；
- 归一化与训练增强配置一致；
- CNN 特征提取器结构一致；
- 分类器结构一致；
- 三源域拼接训练逻辑一致；
- 目标工况评估逻辑一致。

`AGG_FWC` 中的 `IdentityFeatureCombination` 仅作为封装层，已有等价性测试通过。

## 已确认的协议限制

当前五种子结果属于原论文的 legacy 工况迁移复现：原代码在每个 epoch 都访问目标工况，并使用最后一个 epoch 作为最终结果。它可以用于复现原论文训练行为，但不能作为目标域完全盲测的严格泛化证据。

当前 `paper_condition` manifest 已完成记录级审计，但严格 FWC 五阶段回调尚未接入真实训练。因此不能把上述结果称为 FWC 改进结果。

## 结论

1. 复制基线与原始代码在同任务下基本一致；
2. 当前低 Macro-F1 更可能反映该任务、数据和训练协议本身，而不是复制错误；
3. 下一步应先建立 source-only validation / target-once 的正式基线，再接入 FWC 特征组合；
4. legacy 结果与 strict FWC 结果必须分开报告，不能混合比较。
